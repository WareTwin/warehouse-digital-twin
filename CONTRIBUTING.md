# Contributing

1. Create an issue before starting substantial work.
2. Branch from `develop` using `feature/<issue>-short-description`, `fix/<issue>-short-description`, or `docs/<topic>`.
3. Keep changes focused and add tests.
4. Run backend tests and linting; run frontend lint and type checks.
5. Open a pull request into `develop`, complete the template, and request review from the relevant code owner.
6. Never merge your own change when branch protection requires independent approval.

Use conventional commit prefixes where practical: `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `build:`, `ci:`.
